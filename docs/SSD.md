# System Specification Document (SSD)

## 1. System Overview

Система являє собою вебзастосунок у вигляді сайту-візитки для архітектурного бюро. Вона забезпечує можливість перегляду інформації про компанію, послуги та проєкти, а також взаємодію користувачів із контентом через відгуки та форму зворотного зв’язку.

Система також містить адміністративну панель для керування контентом.

---

## 2. Architecture

Система побудована на основі шаблону MVC (Model–View–Controller), який розділяє логіку застосунку на три рівні:

* **Model** — робота з даними та бізнес-логіка
* **View** — представлення даних користувачу
* **Controller** — обробка HTTP-запитів та зв’язок між компонентами

Такий підхід забезпечує модульність, масштабованість та простоту підтримки системи.

---

## 3. Technologies

* Backend: PHP (Yii2 framework)
* Frontend: HTML, CSS, JavaScript
* Database: MySQL
* Development environment: Visual Studio Code
* DB management: phpMyAdmin

---

## 4. System Components

Система складається з:

* Клієнтська частина (браузер)
* Серверна частина (Yii2 застосунок)
* База даних (MySQL)

Взаємодія здійснюється через HTTP/HTTPS запити.

---

## 5. System Modules and Components

### 5.1 Models

Моделі відповідають за роботу з даними:

* AboutUs.php — інформація про компанію
* Comment.php — відгуки користувачів
* ContactForm.php — форма зворотного зв’язку
* LoginForm.php — авторизація користувача
* RegisterForm.php — реєстрація користувача
* Project.php — проєкти портфоліо
* Service.php — послуги компанії
* PublicInfo.php — публічні документи
* User.php — користувачі та ролі

---

### 5.2 Controllers

* SiteController.php
  Публічні сторінки сайту:

  * головна
  * про компанію
  * послуги
  * проєкти
  * контакти

* UserController.php
  Відповідає за:

  * реєстрацію
  * авторизацію
  * роботу сесій

* AdminController.php
  Адміністративна панель:

  * CRUD операції (створення, редагування, видалення)
  * керування контентом
  * модерація відгуків
  * керування користувачами

---

### 5.3 Interaction Flow

1. Користувач надсилає HTTP-запит
2. Контролер обробляє запит
3. Викликається відповідна модель
4. Модель взаємодіє з базою даних
5. Дані повертаються у View
6. View відображає результат користувачу

---

## 6. Database Design

Основні таблиці:

* service (tittle, about, img)
* about_us (tittle, text, img)
* project (name, text, date, img)
* public_info (name, download_path, date)
* comment (user_id, mark, text, is_correct, date)
* user (name, email, password, is_admin, date)

---

## 7. User Roles

### Guest

* Перегляд сайту
* Доступ до публічної інформації

### User

* Усі можливості Guest
* Залишення відгуків
* Відправка звернень через контактну форму
  (дані надсилаються на email власника сайту)

### Admin

* Повний доступ до адмін панелі
* Додавання, редагування та видалення контенту
* Керування користувачами (блокування/видалення)
* Модерація коментарів
* Керування документами та проєктами

---

## 8. API / AJAX Layer

Система використовує серверні PHP-ендпоінти для асинхронної взаємодії з клієнтом.

Основні операції:

* оновлення записів (inline edit)
* створення нових записів
* видалення записів
* завантаження файлів

Всі запити повертають JSON відповідь та використовуються в адміністративній панелі без перезавантаження сторінки.

---

## 9. Data Validation Layer

У системі реалізовано багаторівневу валідацію даних.

### Model validation (Yii2 rules)

Кожна модель містить метод rules(), який забезпечує:

* перевірку обов’язкових полів
* перевірку типів даних
* перевірку формату (email, string, integer)
* перевірку довжини рядків
* перевірку унікальності

### Custom validation

* перевірка пароля через хешування
* перевірка існування користувача
* перевірка завантажених файлів (тип, формат)

### Purpose

* захист від некоректних даних
* цілісність бази даних
* підвищення безпеки системи
* розділення логіки валідації та контролерів

---

## 10. Security

* Хешування паролів (Yii2 security component)
* Перевірка ролей користувачів (is_admin)
* Валідація всіх вхідних даних
* Захист адміністративної панелі

---

## 11. Admin Panel

Адмін панель дозволяє:

* керувати всіма сутностями системи
* редагувати дані в реальному часі (AJAX)
* видаляти записи
* завантажувати файли
* модерувати коментарі
